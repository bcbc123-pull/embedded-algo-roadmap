
# Git VSCode源代码管理面板操作笔记

## 符号含义

- **U(Untracked)：未跟踪文件**
  代表本地新创建的文件，Git已经发现该文件，但**还没有纳入版本管理，没有提交，云端仓库不可见**。
  仅仅出现在更改列表，不等于已经上传仓库。

## Git完整工作流程（VSCode图形界面）

完整链路：本地新建文件 → 暂存(stage) → 提交(commit，本地保存) → 推送(push，上传远程云端)

1. **暂存（Stage）**
   点击文件右侧 `+` 加号，将文件加入暂存区；
   也可以点击更改栏的加号，一次性暂存全部变更文件。

> **作用：挑选哪些文件准备记录到版本库。**

2. **填写提交消息**
   上方消息输入框写规范提交说明。
   示例：
   `docs(phase01): 添加git、miniconda、vscode配置学习笔记`
   格式参考：

- `docs`: 文档/笔记更新
- `feat`: 新增代码、demo功能
- `fix`: 修复bug

3. **点击【提交】按钮**
   执行commit，**仅保存在本机本地Git仓库**，此时Gitee/GitHub网页仓库看不到文件。
4. **点击【推送】按钮**
   把本地的commit同步上传到远程云端仓库。

> **⚠️重点：只提交不推送，修改只存在本机，网页仓库无更新。**

## 文件状态小结

| 标记        | 含义             | 是否上传云端   |
| ----------- | ---------------- | -------------- |
| U Untracked | 新建未跟踪文件   | 否             |
| A Added     | 已经暂存新增文件 | 否（还未推送） |
| M Modified  | 文件被修改       | 否             |

## 仓库提交原则回顾

✅需要提交：源码 `.c`/`.py`/`.ipynb`，`.md`笔记，工程配置json，`.gitkeep`空文件夹占位文件
❌不要提交：编译产物exe/elf/hex，`__pycache__`缓存，IDE本地个人设置，系统垃圾文件，虚拟环境本体

## 实操示例

场景：新增一批学习笔记

1. VSCode资源管理器新建若干`.md`笔记文件
2. 左侧源代码管理面板出现大量U标记文件
3. 点击全部暂存加号
4. 填写提交信息
5. 点击【提交】
6. 点击【推送】
7. 刷新网页仓库，验证文件是否已经出现

## 踩坑记录

1. 只点提交，忘记推送：文件只保存在自己电脑，网页看不到。
2. `.gitignore` 只对未跟踪新文件生效；已经提交过的文件，修改gitignore不会自动删除。
3. `.gitkeep`：Git不跟踪空文件夹，放置该空白文件，用于保留目录结构，允许上传空目录。
