# Git VSCode 源代码管理面板操作笔记

## 1. 文件状态标记

| 标记 | 含义 | 是否上传云端 |
| ---- | ---- | ------------ |
| **U** Untracked | 新建未跟踪文件 | 否 |
| **A** Added | 已暂存的新增文件 | 否（还未推送） |
| **M** Modified | 文件被修改 | 否 |

> **U 只代表「Git 已发现但还没纳入版本管理」**，仅出现在更改列表里，不等于已经上传仓库。

## 2. Git 完整工作流程（图形界面）

> **完整链路：本地新建文件 → 暂存(stage) → 提交(commit，本地保存) → 推送(push，上传远程云端)**

1. **暂存（Stage）**：点击文件右侧 `+` 加号加入暂存区；或点更改栏顶部加号一次性暂存全部。
   > 作用：**挑选哪些文件准备记录到版本库。**
2. **填写提交消息**：顶部输入框写规范提交说明。
   - `docs`：文档/笔记更新
   - `feat`：新增代码、demo 功能
   - `fix`：修复 bug
   - 示例：`docs(phase01): 添加git、miniconda、vscode配置学习笔记`
3. **点击【提交】**：执行 commit，**仅保存在本机本地 Git 仓库**，网页仓库此时看不到。
4. **点击【推送】**：把本地 commit 同步上传到远程云端仓库。

> ⚠️ **重点：只提交不推送，修改只存在本机，网页仓库无更新。**

## 3. 仓库提交原则回顾

- ✅ **需要提交**：源码 `.c`/`.py`/`.ipynb`、`.md` 笔记、工程配置 json、`.gitkeep` 空文件夹占位文件
- ❌ **不要提交**：编译产物 exe/elf/hex、`__pycache__` 缓存、IDE 本地个人设置、系统垃圾文件、虚拟环境本体

## 4. 实操流程

场景：新增一批学习笔记

1. 资源管理器新建若干 `.md` 文件
2. 左侧源代码管理面板出现大量 **U** 标记
3. 点击全部暂存加号
4. 填写提交信息
5. 点击【提交】
6. 点击【推送】
7. 刷新网页仓库验证文件已出现

## 5. 踩坑记录

1. **只点提交、忘记推送**：文件只保存在自己电脑，网页看不到。
2. **`.gitignore` 只对未跟踪的新文件生效**：已经提交过的文件，修改 gitignore 不会自动删除。
3. **`.gitkeep` 占位**：Git 不跟踪空文件夹，放一个空白 `.gitkeep` 文件用于保留目录结构、上传空目录。
