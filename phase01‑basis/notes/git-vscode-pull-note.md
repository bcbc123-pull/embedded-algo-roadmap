# Git 从保存更改到完成推送完整操作笔记
> 重要概念区分
1. **暂存(stage)**：挑选要提交的文件，状态保存在`.git/index`，关闭VSCode不会丢失。
2. **commit(本地提交)**：把暂存的文件生成一个版本记录，只保存在本机电脑，网页仓库看不到。
3. **push(推送)**：把本地commit上传到远程GitHub/Gitee云端仓库。

> 流程：本地文件修改 → 文件+暂存 → 生成本地commit → push推送远程。

## 现象：空消息点提交，弹出 COMMIT_EDITMSG
触发条件：VSCode源代码管理顶部输入框为空，直接点击【提交】按钮。
Git打开内部临时文件 `.git/COMMIT_EDITMSG`，要求填写提交信息；同时顶部消息输入框被锁定为只读，无法输入。
> 文件存放位置：仓库目录下隐藏文件夹 `.git/COMMIT_EDITMSG`，属于Git内部临时文件，**禁止提交到仓库**。

### 方法一：编辑 COMMIT_EDITMSG 文件完成本地commit
1. 打开`.git/COMMIT_EDITMSG`文件。
2. **第一行写入提交信息**，所有以`#`开头的注释行全部保留，Git会自动忽略#注释内容。
示例：
```

输入：docs (phase01): 新增 git 全套操作学习笔记

```
3. `Ctrl+S`保存文件。
> ⚠️Windows环境下`.git`目录文件可能出现只读权限，无法保存，则本方法失效，切换方法二。
4. 关闭该标签页，Git读取文件自动执行本地commit。
成功判断：源代码管理更改列表文件全部消失，Git历史面板出现本次提交记录。

### 方法二：终端命令完成commit（推荐，规避只读弹窗）
文件已经提前完成暂存，不需要重新暂存。打开VSCode内置终端，在仓库根目录执行：
```bash
git commit -m "docs(phase01): 新增git全套操作学习笔记"
```

执行成功，即完成本地 commit。

## 本地 commit 完成之后：推送 Push 上传远程仓库

1. 方式 1：源代码管理面板右上角 `...` → `Push`推送。
2. 方式 2：终端执行

```
git push
```

### 推送弹出 GitHub Sign in 登录弹窗

推送需要账号身份校验：

1. 选择`Browser/Device`标签，点击`Sign in with your browser`。
2. 浏览器打开 GitHub 网页，登录账号并授权 VSCode 访问权限。
3. 授权完毕返回 VSCode，弹窗自动关闭，推送继续执行。

> Token 选项为高级手动模式，新手不使用。授权成功后 VSCode 缓存凭据，后续推送不再重复弹窗。

## 如何判断执行结果

1. 本地 commit 成功：Git 历史图表出现提交记录，更改列表文件消失。

> ⚠️仅仅出现提交记录 ≠ 推送成功，断网也可以生成本地 commit。

2. 推送真正成功：打开网页仓库，刷新页面，能够看到新增的笔记文件；VS 底部状态栏分支显示 `0↑ 0↓`。

## 根治配置，彻底禁用 COMMIT_EDITMSG 弹窗

`Ctrl+Shift+P` →首选项：打开设置 (JSON)，添加配置：

```
"git.useEditorAsCommitInput": false
```

保存文件，重载 VSCode 窗口。

> 作用：不再唤起 COMMIT_EDITMSG 编辑模式，强制使用源代码管理顶部输入框填写提交消息；空消息点提交直接报错，不会锁定输入框。

## 踩坑记录

1. COMMIT_EDITMSG 空白直接关闭标签页：本次提交直接作废，临时文件自动销毁，不生成 commit，文件回到暂存前状态。标签消失不等于提交成功。
2. `.git`文件夹全部为 Git 内部数据库，绝对不要修改、提交`.git`内部文件。
3. 提交 ≠ 推送，提交保存在本机，推送才同步云端。
