
# Git fetch / pull / push 核心命令对比笔记

本篇笔记总结三条最容易混淆的 Git 核心指令，是日常使用频率最高、最关键的三条命令。

## 一、三条命令一句话区分

- **fetch：只下载、不改动、最安全**（查看远程更新）
- **pull：下载 \+ 自动合并**（更新本地代码）
- **push：上传本地代码到云端**（同步本地更新到远程）

## 二、git fetch（推荐新手优先用）

### 作用

从远程仓库 **只拉取最新提交信息**，**不会修改本地文件、不会合并代码**。

相当于：**偷偷看一眼网上更新了什么，不动自己的代码。**

### 命令

```Plain
git fetch
```

### 特点

- ✅ 绝对安全，不会产生代码冲突
- ✅ 只更新本地的「远程镜像记录」
- ❌ 不会改动你当前的任何文件
- ❌ 不会自动合并代码

### VSCode 自动 fetch 弹窗说明

VSCode 询问：**是否定期后台运行 git fetch？**

个人单人仓库建议：**选择 否**

原因：

- 只有自己一个人开发，远程不会出现别人更新
- 不需要后台一直检测网络
- 需要查看远程状态时，手动 fetch 即可

多人团队协作可以选择「是」。

## 三、git pull（新手慎用）

### 本质公式（超级重要）

**git pull = git fetch \+ git merge**

先下载远程代码，然后 **自动合并到本地当前分支**。

### 风险

- 容易产生 **代码冲突**
- 自动合并，你无法预览差异

### 使用场景

确认远程代码干净、想直接更新本地代码时使用。

## 四、git push（上传代码）

### 作用

把**本地已经 commit 的版本**上传同步到 GitHub/Gitee 远程仓库。

只上传本地提交，不会下载任何远程内容。

### 命令

```Plain
git push
```

## 五、三者终极对比表（背诵版）

| 命令  | 动作                             | 是否改本地文件 | 安全性                           |
| ----- | -------------------------------- | -------------- | -------------------------------- |
| fetch | 只下载信息，不合并代码           | 否             | 最高（推荐新手使用）             |
| pull  | 下载远程代码\+ 自动合并到本地    | 是             | 一般，极易产生代码冲突，新手慎用 |
| push  | 上传本地commit提交到远程云端仓库 | 否             | 安全，单人开发常用               |

## 六、个人开发固定流程（你以后一直用这套）

写代码 → 暂存 → 提交\(commit\) → 推送\(push\)

**单人仓库几乎不需要 pull，也不用频繁 fetch**

## 七、易错点总结

- **commit 只是保存本地版本，不是上传**
- **push 才是真正上传到云端仓库**
- fetch 只刷新状态，永远不会弄坏代码
- VSCode 底部双向同步按钮是 pull，新手尽量不点
