# Git fetch / pull / push 核心命令对比笔记

> 这三条命令是日常使用频率最高、也最容易混淆的 Git 核心指令。

## 一、一句话区分

- **fetch**：只下载、不改动、最安全（查看远程更新）
- **pull**：下载 + 自动合并（更新本地代码）
- **push**：上传本地代码到云端（同步本地更新到远程）

## 二、git fetch（推荐新手优先用）

**作用**：从远程仓库**只拉取最新提交信息**，**不修改本地文件、不合并代码**。
相当于：**先看一眼网上更新了什么，不动自己的代码。**

```bash
git fetch
```

- ✅ 绝对安全，不会产生代码冲突
- ✅ 只更新本地「远程镜像记录」
- ❌ 不改动当前任何文件，也不自动合并

### VSCode 自动 fetch 弹窗

VSCode 会询问「是否定期后台运行 git fetch？」。

> **单人仓库建议选「否」**：只有自己开发，远程不会有他人更新，需要时手动 fetch 即可；多人协作可选「是」。

## 三、git pull（新手慎用）

> **本质公式：git pull = git fetch + git merge**（先下载远程代码，再自动合并到本地当前分支）

**风险**：
- 容易产生**代码冲突**
- 自动合并，无法预览差异

**使用场景**：确认远程代码干净、想直接更新本地时使用。

## 四、git push（上传代码）

**作用**：把**本地已 commit 的版本**上传同步到远程仓库，只上传、不下载。

```bash
git push
```

## 五、三者终极对比表（背诵版）

| 命令 | 动作 | 是否改本地文件 | 安全性 |
| ---- | ---- | ---- | ---- |
| fetch | 只下载信息，不合并代码 | 否 | **最高**（推荐新手） |
| pull | 下载远程代码 + 自动合并到本地 | 是 | 一般，极易冲突，新手慎用 |
| push | 上传本地 commit 到远程仓库 | 否 | 安全，单人开发常用 |

## 六、个人开发固定流程

> **写代码 → 暂存 → 提交(commit) → 推送(push)**

**单人仓库几乎不需要 pull，也不用频繁 fetch。**

## 七、易错点总结

- **commit 只是保存本地版本，不是上传**
- **push 才是真正上传到云端仓库**
- **fetch 只刷新状态，永远不会弄坏代码**
- **VSCode 底部双向同步按钮是 pull，新手尽量不点**
